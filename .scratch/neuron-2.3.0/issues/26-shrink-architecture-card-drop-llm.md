# 26 — Shrink the Architecture Card: Drop the LLM, Deterministic Per-File Purpose Only

## Question

Can the architecture card be made small enough to actually fit its
injection budget by removing the per-file LLM summarization step outright,
rather than continuing to truncate a large card at injection time?

## Context

Surfaced 2026-08-08 immediately after [25](25-architecture-card-stable-id-and-truncation.md):
`25` fixed retrieval and made an oversized card degrade to truncation
instead of silent drop, but truncation has its own structural limit — the
card's sections are emitted in a fixed order, so truncating at 6,000 chars
means only the first ~2 of this repo's 14 subsystems ever have their
per-file detail reach any injected session, permanently, regardless of how
many turns or epochs pass.

Investigated where the ~53,000 characters actually come from: `~1-2K` is
header/dependency-contract/subsystem-map (cheap, deterministic, valuable),
and **~50K is per-file "Key Components & Export Contracts" prose**,
generated by `SmolLM2Summarizer.summarizeFile()` (`src/components/
summarizer.ts`) calling a local Qwen1.5-0.5B model per file during
`scanProjectTopology` (`src/scanner/analyzer.ts:227`). That prose is also
the card's main quality problem — real, live examples from this repo's own
`.neuron/decisions.md`: `src/scanner/ingest.ts` described as "This file
defines a JavaScript function called 'bluestcardid'", `src/harnesses/
copilot.test.ts` rendered partly in Portuguese, `src/commands/feedback.ts`
containing a stray fragment `"(E026)"` / `"(F257"`. **Maintainer's direct
instruction: remove the LLM call outright** — at this size, the
summarization isn't earning its cost, and a 0.5B model's per-file prose is
not reliable enough to keep shipping as the card's dominant content.

**Scoped precisely, not to the whole model**: `summarizeFile()`'s model call
shares its underlying loader (`getTextGenerator()`, `src/components/
generator.ts`) with write-side enrichment (`src/components/enricher.ts`),
a separate, already-established feature (tag/importance inference on
ordinary memory writes) with its own design history — this ticket does not
touch that. Confirmed via grep: `summarizeFile` has exactly one call site
(`analyzer.ts:227`, feeding `synthesizeArchitecture`'s per-file purpose
text) — nothing else in the codebase depends on its LLM branch specifically.
`neuron init`'s "Initializing ONNX Summarizer model" preload step stays,
since enrichment still needs the same shared model warm.

Also relevant: `summarizeFile()` already skips its LLM branch under
`NODE_ENV=test` (line 116), falling straight to the deterministic JSDoc-
comment-extraction / AST-signature fallback that already exists in the same
function (lines 140-160) — meaning every existing test already exercises
only the code path this ticket makes the *only* path. Low regression risk
by construction, not by luck.

## Scope

1. Remove `summarizeFile()`'s LLM-inference branch (`src/components/
   summarizer.ts` lines ~116-137: the `getGenerator()`/`generator(prompt,
   ...)` call and its surrounding `if` guard) so every call always falls
   through to the existing deterministic fallback chain (JSDoc-comment
   extraction, then the AST-signature-based `generateFallbackSummary`).
   Delete the now-dead prompt-construction and `sanitizeSummary` machinery
   only if nothing else calls it — `sanitizeSummary` also cleans the
   cache-load path (line 71), so check before removing.
2. `summarizeFile()`'s on-disk cache (`scan_summaries.json`,
   `loadCache`/`saveCache`) and its `preloadModel` are specific to the
   model branch being removed — decide whether to delete them or leave them
   dead/unused, and record which.
3. **Measure the actual result on this repo.** Run a real `neuron scan` and
   report the new card's total character count against the old ~53,000 and
   against `SESSION_START_CHAR_BUDGET` (6,000) — deterministic fallback text
   is shorter and more uniform than free-form LLM prose, but report the real
   number rather than assuming it now fits. If it still doesn't fit whole,
   `25`'s truncation remains the safety net, not a fix this ticket owes.
4. Regenerate this repo's own `.neuron/decisions.md` blueprint card (a real
   `neuron scan`) so the dogfooded store reflects the new deterministic
   content rather than the old model-generated prose — consistent with how
   `25` and `11` both left this repo's own store in the fixed state before
   their sessions ended.
5. `neuron init`'s "Initializing ONNX Summarizer model (Qwen1.5-0.5B)"
   preload stays (enrichment still needs it) — check whether its progress
   label should change now that scanning no longer uses it, so the message
   shown to a user doesn't misattribute why the model is loading.

## Answer

**LLM branch removed entirely** from `summarizeFile()` (`src/components/
summarizer.ts`) — no `getGenerator()`/model-inference call anywhere in the
function anymore; every call falls through to JSDoc-comment extraction,
then the AST-signature fallback. **Cache mechanism deleted outright**
(`loadCache`/`saveCache`/`cacheFilePath`/the in-memory `cache` Map, and
`sanitizeSummary`, all of which existed solely to amortize the now-removed
model call — a deterministic string computation doesn't need disk-backed
caching). `preloadModel()`/`getGenerator()` **kept** on the class: `neuron
init` still calls `preloadModel()` to warm the same shared model loader
(`getTextGenerator()`) that write-side enrichment (`enricher.ts`) calls
directly for its own, unrelated purpose — confirmed via grep that
`summarizeFile` had exactly one call site (`analyzer.ts`) and enrichment
never went through `SmolLM2Summarizer` at all, so nothing else was touched.
Also removed `analyzer.ts`'s scan-time `preloadModel()` call (line ~180) —
dead weight once `summarizeFile` no longer uses the model, saving the
~3.2s load on every scan too.

**Measured, honestly, in two steps** — the maintainer asked after seeing
the first number that removing the LLM alone barely helped:

1. LLM removed only: this repo's real blueprint card went 54,924 → 53,487
   bytes (**~2.6%** smaller). Root cause: only files *without* a leading
   JSDoc comment ever hit the LLM branch (60 of 128 file entries, ~47%),
   and the deterministic AST-fallback template that replaced it was nearly
   as verbose as the model's one-sentence output (`"Function X in file.ts
   (Methods: a(), b()) handles utility and command processing."`).
2. **Fallback template also tightened**, per the maintainer's explicit
   follow-up: `synthesizeArchitecture`'s own render already shows the
   filename (bold header) and export list (`Exports: ...`) alongside each
   entry, so the fallback repeating either was pure redundancy. Rewrote
   `generateFallbackSummary` to drop the filename restatement and the
   decorative closing clause (`"manages module operations and interface
   contracts"` / `"handles utility and command processing"`), keeping only
   what wasn't already shown — method signatures. Result: 54,924 → **49,243
   bytes (~10.3% smaller)**.

**Quality improved substantially either way** — the real point of the
maintainer's original instruction: no more garbled or non-English output
(prior real examples from this repo's own store: `src/scanner/ingest.ts`
described as "This file defines a JavaScript function called
'bluestcardid'", `src/harnesses/copilot.test.ts` rendered partly in
Portuguese). Every description is now fully deterministic and reproducible.

**Honest limit**: 49,243 bytes is still far past the 6,000-character
`SESSION_START_CHAR_BUDGET` — `25`'s truncation remains necessary, just
truncating less (confirmed: the injected card now reaches into
`src/commands` before cutting off, versus stopping mid-`src` before this
ticket). The remaining size is now dominated by legitimately valuable,
hand-written JSDoc rationale comments already in this repo's source (e.g.
`src/commands/hook.ts`'s and `src/scanner/ingest.ts`'s own doc comments,
extracted verbatim) — cutting further would mean truncating genuine content
per file, a different and more invasive tradeoff than "remove the
unhelpful LLM output" was asking for, so left alone.

This repo's own `.neuron/decisions.md` blueprint card regenerated via a
real `neuron scan` (id `dff93b46-cf14-993a-2067-2b9e994527b3`, unchanged —
`25`'s stable-id upsert). `24`'s `captured-card.txt` recaptured against the
new card via a real `neuron hook claude-code session-start` invocation.
`summarizer.test.ts` updated to match (no more `forceFallback` option,
`summarizeFile` is now synchronous). `npm test` 559/559 both before and
after the template tightening pass; `tsc --noEmit` clean.
